# HueFrame "卡片" Tab 重设计——设计规范

> 承接 [2026-07-01-photo-colorcard-tool-design.md](2026-07-01-photo-colorcard-tool-design.md) 的产品定位。本文档基于 Google Stitch 生成的 6 张探索稿（用户提供于 `/Users/leo/Downloads/stitch_hueframe_photo_palette/`）与用户逐项确认后的结果，是"卡片" Tab 的正式设计规范。

## 背景

用户提供了一批 Stitch 生成的设计稿（含一份完整设计系统 `DESIGN.md: Ethereal Botanical`），比当前 MVP 覆盖的功能范围大得多，包含单图色卡、取色精细编辑、版式比例配置、命名滤镜、宫格切图、Library 等模块。经与用户逐项对齐：

- **整体信息架构**：App 采用底部三 Tab 导航——**卡片 / 宫格 / 裁剪**。三者范围差异大（卡片=已有 MVP 逻辑改视觉；宫格=需要新写网格切分算法；裁剪=全新的裁剪+标记+贴图能力，范围本身待定），拆成 3 份独立的设计/实施周期。
- **本文档范围**：仅"卡片" Tab。"宫格""裁剪"留待后续单独立项。

## 设计系统

直接采用参考文件夹 `ethereal_botanical/DESIGN.md` 定义的设计系统，不重新定义色板/字体/圆角规则。关键要点：

- **色板**：近白暖背景 `#f9f9f8`，主文字 `#1a1c1c`（非纯黑），主色调 `#57605d`（灰绿色系），强调用淡薄荷绿 `#e0e9e4` 容器色，不用高饱和撞色
- **字体**：标题用衬线体 Libre Caslon Text（编辑感、刊物感），正文/UI 用 Inter，字重偏轻（400），行高宽松（1.6）
- **圆角**：卡片/输入框 4px，大图/主视觉容器 12px；避免直角，也避免过度圆润的胶囊形
- **层次**：不用常规投影，用"色调分层"（更浅/更冷的色块叠在底色上）表达层级；必要时用超柔和的 ambient glow（30-50px 模糊、3-5% 透明度）
- **组件基调**：按钮低对比度色块、卡片用 1px 细描边而非投影、列表间距宽松、分割线极淡或直接留白替代

## 页面结构

### 顶部栏
Logo/标题 "HueFrame" + 中英文切换（ZH/EN，对应色名语言，语义与现有 `LanguagePicker` 一致）。不设汉堡菜单、不设独立设置入口——这些是 Stitch 稿里对应旧的 4-Tab（Library/Editor/Layouts/Export）导航遗留的元素，当前 3-Tab 结构下不需要。

### 底部导航
三个 Tab：**卡片 / 宫格 / 裁剪**。当前实现范围仅"卡片"，另外两个 Tab 先占位（可禁用或跳转到"敬请期待"占位页，具体交给实施计划决定）。

### "卡片" Tab —— 空状态
未上传照片时展示引导页，采用 Stitch `hueframe_4` 稿的内容结构：
- 大标题："给照片，配一套颜色。"（Libre Caslon Text）
- 居中虚线圆角上传区域，内含极简上传图标 + 引导文案 "CLICK OR DRAG TO UPLOAD"
- 格式提示小字："本地解析支持 JPG / PNG / WEBP"

### "卡片" Tab —— 已上传状态
结构从上到下：

1. **照片 + 色卡预览区**（固定展示，不随下方 Tab 切换而消失/重排）：当前选中滤镜实时效果 + 当前选中版式的最终拼贴效果，所见即所得。
2. **二级 Tab 组**（位于预览区下方，非顶部——为未来扩展更多 Tab 预留横向空间）：**滤镜 ｜ 版式 ｜ 调色 ｜ 信息**
3. **导出按钮**：固定在页面底部，不随二级 Tab 切换隐藏。

## 二级 Tab 详细规格

### 滤镜 Tab
- 4 个选项，沿用 MVP 现有命名：**无滤镜 / 暖调胶片 / 冷调胶片 / 复古正片**（不改用 Stitch 稿的"清透/柔光/黑白/暖阳"命名，避免引入"黑白"这个 MVP 没有的新滤镜类型）
- 每个选项显示**缩略图预览**（对当前照片实时应用该滤镜后的小图），而非纯文字按钮
- 选中态需要清晰的视觉反馈（符合设计系统：淡色块高亮，非粗边框）

### 版式 Tab
- 版式选择：经典色带 / 杂志封面（复用现有两套模板）
- **比例切换**：4:5 / 1:1 / 16:9（新增能力，当前 MVP 尺寸固定为 800×1000）
- **留白边距滑杆**：控制照片/色卡整体外围留白像素值（新增能力）

### 调色 Tab
- 取色结果以**列表**形式展示：每项显示色块（大色块本身可点击）+ 色名 + HEX 值 + 占比 %
- 排序规则：按取色权重（提取时的占比）排序，**不做**"整体重新生成/打乱"操作
- **单色块微调**：点击某个色块弹出取色器，用户可手动微调/替换该颜色；仅影响这一个色块，不影响其他色块或重新触发整体取色算法
- 中英色名切换沿用顶部栏的 ZH/EN 控件，不在此 Tab 内重复放置

### 信息 Tab
- **地点**：默认由 EXIF GPS 反查填入（无 GPS 时兜底"未知地点"，逻辑沿用现有 `geocoding.ts`），**支持手动编辑**（新增能力）
- **时间**：默认由 EXIF 拍摄时间填入，**支持手动编辑**（新增能力）
- **水印开关**：控制导出图右下角是否显示 "HueFrame" 小 logo/文字水印（新增能力，默认开启还是关闭留给实施阶段决定，建议默认开启）

## 版式差异化——数据结构约定

经典色带与杂志封面在"调色"“信息” Tab 的实际视觉需求不同（例如杂志封面的色块只是角标点缀、经典色带的色块是主视觉），但**本轮不做差异化 UI**——两个版式共用同一套调色/信息控件与同一套 `CardConfig` 字段。

约定：底层数据结构设计上要为未来的差异化留出扩展空间，即 `CardConfig`（或其等价类型）不应假设"所有版式共享完全相同的可配置字段集"，应允许后续给单个版式类型追加专属配置（如未来给杂志封面加"标题字体选择"字段）而不需要推翻现有结构。具体如何扩展（如按 template id 做字段的可选/条件类型）留给实施计划阶段设计。

## 明确不做的部分（本轮）

- "宫格"Tab 与"裁剪"Tab 的具体功能——留待各自独立的设计文档
- Stitch 稿里的滤镜改名（清透/柔光/黑白/暖阳）与新增黑白滤镜
- 取色列表的"整体重新生成/打乱"功能
- Library（历史记录/多图管理）
- 版式间的差异化 UI（调色/信息 Tab 的控件按模板显示不同内容）——仅要求数据结构支持，不要求本轮做出差异化界面

## 开放问题（留给实施计划阶段决定）

- 底部导航"宫格""裁剪"两个未实现 Tab 的具体占位交互（禁用态 vs 占位页）
- 水印开关的默认值（开启/关闭）
- 版式的比例切换（4:5/1:1/16:9）与留白滑杆具体如何影响两套模板各自的内部排版计算
