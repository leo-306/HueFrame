# HueFrame "宫格" Tab —— 设计规范

> 承接 [2026-07-02-card-tab-redesign.md](2026-07-02-card-tab-redesign.md) 中"宫格""裁剪"留待独立立项的决定。本文档是"宫格" Tab 的正式设计规范，"裁剪" Tab 留待后续单独立项。

## 背景

底部导航现有三个 Tab：卡片 / 宫格 / 裁剪。"卡片"已实现并完成 shadcn/Tailwind 迁移，"宫格""裁剪"此前是禁用占位符（"敬请期待"）。本轮把"宫格"从占位符实现为真功能，"裁剪"仍保持占位状态、留给下一轮独立设计。

## 功能定位

"宫格"是一个与"卡片"完全独立的图片网格处理工具，包含两个子模式：**切分**（一张图切成网格状的多块拼接大图）和**拼图**（多张图按网格拼成一张大图）。两个子模式共享同一套网格规格选择器和间距控件。

## 页面结构

"宫格" Tab 顶部（预览区下方）用二级 `Tabs`（复用"卡片"Tab 里 `CardTabs` 已验证的 shadcn Tabs 模式）在**切分 / 拼图**之间切换。两个子模式各自维护独立状态（已上传的图片、网格规格、间距），互不影响，切换时不清空对方状态。

### 切分模式

1. **上传**：复用现有 `UploadZone`，单图上传。
2. **网格规格**：`GridSizePicker` 组件，预设 `3×3` / `2×2` / `1×3`（横向三联）按钮 + "自定义"输入行数、列数（各限制在 1-6 之间，超出范围时钳制到边界值并给出提示）。
3. **切分规则**：按行列直接对原图的像素坐标做等分切割——不裁剪、不改变整图的原始宽高比。例如一张 1200×900 的图选 3×3，每块就是 400×300，网格线严格按行列比例落在原图坐标上。
4. **间距调节**：复用现有 `MarginSlider` 组件与交互模式，控制块与块之间的间隙像素值（默认小间距，如 8px）；间隙区域用页面背景色（`--color-surface`）填充。
5. **预览**：展示原图叠加网格分隔线（预览态可以画线以便用户判断切分位置，导出态间隙用背景色块，不画线）。
6. **导出**：合成**一张完整的网格大图**（切分后的各块 + 间距 + 背景色填充），不做多文件下载。

### 拼图模式

1. **上传**：多图上传，需要支持 `multiple` 的文件选择/拖拽——新增 `MultiUploadZone` 组件（在现有 `UploadZone` 基础上把 `<input>` 的 `multiple` 属性打开，`onFilesSelected` 回调传出 `File[]`）。
2. **网格规格**：与切分模式共用同一个 `GridSizePicker` 组件。
3. **填充规则**：按用户选择图片的顺序，从左到右、从上到下自动流入网格单元格，不支持拖拽调整位置。
   - 图片数 < 格子数：多余的空单元格用 `--color-surface-container` 色块占位。
   - 图片数 > 格子数：只使用前 N 张（N = 行数 × 列数），并在预览区上方给出文字提示"仅使用前 N 张"。
4. **单元格裁剪策略**：每张图片用 `cover` 策略（居中裁剪填满，无留白）填入对应单元格，与现有 `cardRenderer.ts` 里照片铺满逻辑一致，复用其绘制辅助函数。
5. **间距调节**：与切分模式共用同一个 `MarginSlider` 组件实例（拼图模式下是新的状态值，不与切分模式共享数值）。
6. **导出**：合成**一张完整的拼接大图**。

## 与"卡片"功能的联动

两个子模式的结果预览区下方都放一个"生成色卡"按钮（非自动触发，用户主动点击）。点击后：

1. 把当前结果 canvas 转成一个新的 `HTMLImageElement`（复用 `App.tsx` 里已有的 canvas → Image 转换模式）。
2. 将其作为"新照片"送入现有的 `buildCardConfig` 处理管线（等同于用户在"卡片" Tab 重新上传了一张图）。
3. 把 `activeTab` 切换到 `'card'`。

这是单向的、一次性的"接力"传值，不引入宫格与卡片两个 Tab 之间的持续状态耦合——宫格 Tab 的状态在接力后照常保留，用户可以切回来继续用宫格的其他功能。

## 技术设计

### 新增文件

| 文件 | 职责 |
|---|---|
| `src/lib/gridLayout.ts` | 纯函数：给定图片尺寸/张数、行列数，计算出每个单元格的坐标、尺寸、（拼图模式下）cover 裁剪的源矩形参数。不涉及 canvas，只做几何计算，便于单元测试覆盖边界情况。 |
| `src/lib/gridRenderer.ts` | 消费 `gridLayout.ts` 的计算结果，在 canvas 上绘制最终的切分图/拼接图（含间距背景色填充）。拼图模式下的 cover 绘制逻辑从 `cardRenderer.ts` 里提取复用，不重复实现。 |
| `src/components/grid/GridTool.tsx` | "宫格" Tab 的容器组件：二级 Tabs 切换 + 两个子模式状态管理 + "生成色卡"接力回调的对外接口。 |
| `src/components/grid/GridSizePicker.tsx` | 预设网格按钮 + 自定义行列输入，双模式共用。 |
| `src/components/grid/GridSplitPanel.tsx` | 切分模式面板：上传区 + 规格选择 + 间距滑杆 + 预览 + 导出 + 生成色卡按钮。 |
| `src/components/grid/GridCollagePanel.tsx` | 拼图模式面板：多图上传区 + 规格选择 + 间距滑杆 + 预览 + 导出 + 生成色卡按钮。 |
| `src/components/grid/MultiUploadZone.tsx` | 支持多选/多拖放的上传组件，视觉上与 `UploadZone` 保持一致（同样的虚线圆角容器风格）。 |

### `App.tsx` 改动

- `BottomNav` 的 `grid` 选项从 `disabled: true` 改为可点击。
- `activeTab === 'grid'` 分支渲染 `<GridTool onGenerateCard={...} />`，`onGenerateCard` 回调复用 `handleFileSelected` 的图片处理入口（把合成后的 canvas 转 Blob/File 或直接转 Image 后调用现有管线），并在回调内把 `activeTab` 设为 `'card'`。

### 测试策略

沿用项目既有 TDD 约定，每个新 `.ts`/`.tsx` 文件配套 `.test.ts(x)`。重点覆盖：

- `gridLayout.ts`：1×1、行列不能整除图片尺寸、自定义行列边界值（1 和 6）、图片数量少于/多于/等于格子数三种情况下的坐标计算。
- `GridSizePicker.tsx`：预设点击、自定义输入的钳制行为。
- `GridCollagePanel.tsx`：图片数量与格子数不匹配时的提示文案与占位色块渲染。
- "生成色卡"回调：验证点击后触发的回调参数（图片）与 Tab 切换。

## 明确不做的部分（本轮）

- 拼图模式的拖拽调整图片位置/互换顺序——固定为按上传顺序自动填入。
- 切分模式导出多张独立小图/打包下载——统一导出为一张大图。
- 网格单元格的旋转、单独裁剪范围手动调整等精细编辑能力。
- "裁剪" Tab 的任何功能——留待独立设计。
- 宫格结果与色卡功能的双向同步（例如色卡改了滤镜后同步影响宫格）——仅支持宫格→卡片的单次单向接力。

## 开放问题（留给实施计划阶段决定）

- 自定义行列输入超出 1-6 范围时的具体提示文案与交互（是否需要错误态样式）。
- 预设网格按钮与自定义输入框在 UI 上的具体排列方式（沿用 `TemplatePicker` 按钮组风格 + 独立自定义区块，还是别的布局）。
- 拼图模式下"仅使用前 N 张"提示的具体展示位置与样式细节。
